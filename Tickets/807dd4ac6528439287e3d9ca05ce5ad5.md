# Release-independent package builds

publish_localnuget now decides package versions after one version-free build (NuGetManager 9ab5bb0): no package version reaches the compiler, an unchanged package is reused, and a new package must not lower a published assembly version. Microsoft.MSBuildCache.Common/Local/SharedCompilation were last published at 1.0.1 with AssemblyVersion 1.0.1.0; the declared version is the default 1.0.0, so the next build would be rejected.

Change (agreed in chat): Directory.Build.props turns SourceLink and source-control queries off for every project (the publisher keeps the commit out of compilation only when the whole solution does), and for the non-test src projects freezes AssemblyVersion at 1.1.0.0, stops generating FileVersion/InformationalVersion, replaces the embedded PDB with none and maps source paths, as in MerkleCompiler (cbaf70f) and NuGetManager (9ab5bb0). FileAccessDataCapabilities reads MSBuild's InformationalVersion, not this repository's. Tests keep embedded PDBs.

## Summary

Packaged MSBuildCache assemblies no longer depend on the release: AssemblyVersion 1.1.0.0, no release FileVersion/InformationalVersion, no PDB, PathMap, SourceLink off.
Consumer impact: behavior - the packaged assemblies have AssemblyVersion 1.1.0.0, no FileVersion/InformationalVersion and no PDB.
