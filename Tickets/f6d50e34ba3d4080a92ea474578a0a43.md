# Additional input roots and external dependencies in the test cache

Builds hash inputs only under the repository (git) and the NuGet package root; any other file a build reads is left out of fingerprints. A project that references a sibling repository (ScriptMcp -> GuardedMcp.Garnet -> Garnet) can therefore reuse cached outputs after the sibling changes. The caller-target cache (RunTargetAsync) instead throws "Target dependency is outside the cache repository", so such test projects never reuse results.

- New setting MSBuildCacheAdditionalInputRoots: directories whose files are hashed by content when a build reads them, after the repository and the package root. Configured roots add a plugin-settings fingerprint entry, so entries recorded without them are not reused.
- RunTargetAsync describes a dependency outside the repository by its project file and its TargetPath assembly, both hashed by content, and identifies it by its absolute project path.
- README documents the setting.
- Tests: fingerprint segregation, composition hashing inside and outside a root, and a caller-target run with an external dependency (reused when unchanged, re-run when its output or project file changes).

## Summary

New MSBuildCacheAdditionalInputRoots: files a build reads under configured roots, such as sibling repositories, are hashed by content, so dependents miss when a sibling changes; the repository's own untracked files stay excluded. The caller-target cache describes dependencies outside the repository by their project file and output assembly instead of failing.
Consumer impact: behavior - configured roots change fingerprints; caller-target results with external dependencies become reusable
