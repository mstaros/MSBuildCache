# Additional input roots exclude the temporary directory

With a drive as an additional input root, files a build reads in the temporary directory (MSBuild temp files, Exec scripts) would enter fingerprints under random paths and never match again. Excluding temp through MSBuildCacheIgnoredInputPatterns is wrong: those patterns apply to every input, so a repository under temp would lose all its inputs and always hit.

- Additional-root hashers exclude the repository root and the temporary directory; the exclusions are passed in, so tests can use their own.
- The README states both exclusions.
- The composition test covers a file under an excluded temporary directory.

## Summary

Additional input roots never claim the temporary directory, whose random paths would never match again, as well as the repository's untracked files; the exclusions live in the hasher instead of the global ignore patterns, which would also drop a repository's own files when it sits under temp.
Consumer impact: behavior - files read in the temporary directory stay out of fingerprints under additional roots
